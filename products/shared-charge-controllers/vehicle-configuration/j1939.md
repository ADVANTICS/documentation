# SAE J1939

By default the controller talks to your vehicle over the ADVANTICS generic CAN interface. If
your BMS speaks **SAE J1939** instead, the controller can bridge onto it: set
`enable_j1939_bridge` and the same information is carried in J1939 PGNs.

!!! warning "The controller does not claim its address"
    `device_address` is static and the address claim protocol is not implemented. You must
    make sure the address you configure is not already taken by another device on that bus.

Entries marked **advanced** are hidden in the Web UI until you switch to expert mode.

## `[j1939]`

- **`default_priority`**: Priority applied to J1939 messages. Only when `enable_j1939_bridge` = `true` (default: `0`)
{: #default_priority }
- **`device_address`**: J1939 source device address that should be used by the controller. Note that this address is static and that the controller does currently not implement the address claim protocol. Thus you need to make sure that the address configured here does not clash with other J1939 devices on the same bus. One of `0` to `253`. Only when `enable_j1939_bridge` = `true` (default: `0`)
{: #device_address }
- **`enable_j1939_bridge`**: Uses J1939 for the communications with the backend (default: `false`)
{: #enable_j1939_bridge }
- **`j1939_can_if`**: CAN interface to which J1939 messages should be sent. Only when `enable_j1939_bridge` = `true` (default: `can0`)
{: #j1939_can_if }
- **`peer_address`**: The device address used by your side. Default (0xFF) is to accept messages from any device address, but in case of PGN conflicts you may want to filter in the messages from a given source address. One of `0` to `255`. Only when `enable_j1939_bridge` = `true` (default: `255`)
{: #peer_address }
- **`vendor_pgn_offset`**: Can be used to solve ID conflicts in the J1939 vendoring space. All ADVANTICS vendor PGNs will be shifted by this offset. One of `0` to `192`. Only when `enable_j1939_bridge` = `true` (default: `0`) **advanced**
{: #vendor_pgn_offset }
